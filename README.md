# 知衡 · 高中数学教学反馈工作台

Windows 本地软件。导入原卷和学生作答，AI 整理多小问评分标准、定位跨页作答、逐点预批；老师对照原卷确认分数与表现，再安排讲评、辅导与复测。也可完全人工录分，基础统计无需 AI。

**当前源码 0.3.1 为教师辅助阅卷试用版。** 可脱离 Codex，通过配置的模型 API 独立运行。历史 0.3.0 的公开手写答卷对照见交付验收报告；0.3.1 的工程修复与开源检查见[审核记录](docs/audit-open-source.md)。公开样例不代表真实班级，仍需教师核对，不宣称全题型自动定分或已证明改善教学效果。现有 0.3.0 安装包不包含 0.3.1 的修复。

## 独立运行与适用范围

程序负责上传、PDF 渲染、识卷、评分标准整理、作答定位、逐点预批、复核和导出；这些操作不需要 Codex。智能功能需要支持图片、兼容 Chat Completions 的服务，地址后追加 `/chat/completions`。人工录分、基础统计和本地资料保存不需要模型 API。不同服务的模型能力和参数支持可能不同，填写连接信息并不等于已验证该模型可用。

当前的自适应范围有明确边界：

- 题目数量、小问层级、评分点、分值和成绩列随考试结构生成；老师可以调整题型、答案和给分规则。
- 识卷提示、示例知识目录和已完成的模型实测以数学为主。其他学科可编辑题目与规则，但算法、代码、图算法等尚无独立 API 盲评验收。
- 每位学生每次上传一份包含全部作答的 PDF，或一张包含完整作答的图片。双面及多页照片须先合成 PDF；同批同学生多份文件会阻止上传。程序按文件名匹配名单，不自动按照片编号合卷，也不读取卷头姓名、学号。后续重新上传会作为新版本，预批使用最新完整文件。
- Excel/CSV/TSV 导入读取第一个工作表、第一行表头。学号接受“学号”、`Student ID`、`student_id`、`Student Number`、`student_number`、`number`；姓名接受“姓名”、`Name`、`Student Name`、`student_name`，英文不区分大小写。成绩列必须对应本场题号，支持 `Q` 前缀；标题行、多表头、合并姓名列和任意列映射尚不支持。先下载模板并检查导入预览。
- 视觉模型可能误读手写、旋转、小字和图形。建议分数保留原图证据，教师确认后进入正式成绩；缺页和证据不足不应自动记零。

历史模型名称不保证模型实现不变。例如 DeepSeek 官方现已将旧 `deepseek-v4-flash-vision-exp` 名称转到新的 Flash 模型；历史评分结果不能作为当前模型的等效验证。[服务商说明](https://api-docs.deepseek.com/)

## 教师从这里开始

1. 建立班级，核对学号和姓名，再新建考试。
2. 首次请信息老师配置智能服务。日常无需理解模型或提示词。
3. 上传同一套题面 PDF，选择题面页（如1-4），排除答案页。每两页保存一批，失败只重试未完成页。
4. 核对清单，无需转写完整题干。满分未知可留空，小分暂存为草稿；知识点待确认不影响逐题统计。
5. 可直接录入全班小分；或进入“AI 阅卷与复核”，上传可选参考答案，核对全班共用标准，再上传学生原卷自动预批。
6. 看原图后分别确认分数与逐技能表现。续页漏选、区域不全、识别错误均可编辑修正；已有教师分数默认保留。
7. 查看个人与班级反馈；需要智能建议时再调用服务。
8. 到“教学与复测”调整辅导名单，写明短测任务和标准，记录结果。

详见[教师操作指南](教师操作指南-0.3.md)。

## 自行修正与恢复

题号、满分、题型、知识点、技能、页码均可修改。主要知识点改变后需重新确认。可以暂停某题知识诊断，同时保留分数和总分。重新识卷只补新题，同题号保留教师原有修改和成绩。

合并、拆分、取消独立计分题先预览班级影响。合并只对完整小分相加；拆分不自动分摊分数。原始记录保留，尚无后续修改时可撤销结构调整。

识卷核对、评分标准、作答区域、逐点复核、手工录分、报告修订及辅导安排支持草稿恢复。报告保存修订版后导出，原版保留。相关标准、区域、原卷或最终分数改变后，旧逐点解释暂时排除，重批复核即可恢复；不会默默混入新报告。

预批按逻辑小问、每批最多三个评分点执行。每批完成即保存；同样输入继续处理时复用已有结果，失败从未完成批次继续。每个技能独立判断，缺少过程证据不从得失分推断掌握或不会。

学生页面仅匹配到一道题时保留整页，避免框选漏掉后面的作答；多题页面按题框选，教师仍需检查续页。某批回复被截断时自动改为逐个评分点处理；网络失败后点击“继续预批”保留先前进度。

模型标记作答页缺失或完整性不确定时，不合计建议总分；未收到的步骤保留待核对，不能视作零分。该保护仍依赖识别信号，老师必须对照完整原卷确认。

## 分析边界

数字由程序计算。全卷统计只纳入完整最终成绩；逐题使用该题有效人数；知识题组使用全部完成该题组者的加权得分率。未录入、草稿、零分、缺考、不适用分别保存。

学情请求不含完整题干、答案、原卷图片或未确认成绩，使用最终成绩、程序统计、备注及教师已确认的逐技能表现。班级备注每题最多四条、每个技能最多四条证据样例，不代表全班。结构字段不发送姓名、学号；备注中匹配到的名单姓名会替换为匿名编号，仍建议不要填写额外个人信息。

多技能统计按已核对学生去重，区分明确错误、已表现、证据不足与前错影响。状态人数可以交叉，不相加、不自动换算掌握率，不把同一步的得失分复制到所有关联技能。

AI 报告观察段由程序根据引用生成；无效引用或夹带未经核验成绩数字的建议逐项过滤。教学建议仍需教师审核，引用合法不等于建议必然正确。满分备注可能是未扣分问题或订正记录，不代表失分。

## 开发和测试

需要 Node.js 22.13 以上及 npm；本轮源码使用 Node.js 24 验证，Windows 用于打包与桌面验收。

~~~text
npm ci
npm run dev
npm test
npm run build
npm run dist
~~~

持续集成使用隔离的模拟资料，不配置模型密钥，不调用付费 API。源码发布使用白名单打包及凭据检查：

~~~text
python scripts/package-source.py
python scripts/check-release-secrets.py --source-only
npm audit --omit=dev
~~~

测试中的发布检查需要 Python 3.9 以上（仅使用标准库，可用 `PYTHON` 环境变量指定解释器）；本轮使用 Python 3.12 验证。应用本身无需 Python。Windows 桌面二进制须另行构建、检查依赖许可证、执行启动与安装验收，不能用源码测试代替。

本地回归中的故障注入与真实测试分开。scripts/release-live.mjs 使用官方服务，须通过环境变量提供 DEEPSEEK_API_KEY，会产生费用。历史样卷不附在源码包中，来源与准备脚本见 scripts/prepare-release-papers.py；重新运行前须准备对应材料。

桌面仅监听本机随机端口。ZHIHENG_DATA_DIR 可指定隔离资料目录，不要让多个开发进程同时打开同一资料库。正式资料建议定期导出.zhb备份。

## 发布范围与限制

- 单教师、单机、相同计分结构，不提供多人协作、校级权限或公网部署。
- 不同学生选做不同选考题时，先分成计分结构一致的考试；当前不能自动调整个人选考分母。
- 结构迁移工具处理独立计分题；复杂父子结构需先在题目编辑中核对。
- 模型仍可能漏题、错认分值、标签过宽。请核对清单，不能只看警告标记。
- 手写验证仅覆盖验收报告列出的公开样例；不能外推为全题型或全体学生的准确率。不能由小分推断耗时、选项分布、完整推理或长期能力。
- Windows 包尚无代码签名，可能出现系统信誉提示。分发时附SHA-256；校园推广前应完成签名和真实教师试用。

## 快速启动本机网页版

安装 Node.js 24，下载并解压源码，在项目目录依次运行：

~~~text
npm ci --ignore-scripts
npm run build
npm run server
~~~

浏览器打开 <http://127.0.0.1:4318>，保持终端运行。资料库首次启动自动创建。此方式仅运行本机网页版，跳过 Electron 二进制安装，不需要 Python；人工录分、查看成绩和导出可以直接使用。AI 功能需在设置中填写支持图片的兼容 API 地址、密钥及对应模型，并核对评分标准。该地址仅供本机访问。

完整回归与发布检查另外需要 Python，说明见 [TESTING.md](TESTING.md)。当前 0.3.1 发布源码，不附旧安装包、真实学生资料、成绩、原卷、运行配置或接口日志。
